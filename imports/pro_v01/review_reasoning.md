# 推理题与评分器审查记录（内部来源审计）

范围仅为导入包的两个推理题及scoring.py；统一比赛编号为R3、R4，对应原包R1_diagnosis、R2_dispatch。本记录保留来源映射，不建立单独来源榜单。原件位于imports/pro_v01/upstream/，未作修改；修复仅落在适配副本及本审查记录。

## 结论

当前适配副本可以作为统一题库中的两道中等至中高难度策略优化题，但不能把计划中的高难规模或固定公开seed的结果宣传为已完成的高难隐藏测试。发现并实际修复了评分可被输入引用篡改、宽松动作类型与不受控异常等阻断。正常策略的原版/适配版分数在1e-12容差内一致。

本次先逐行阅读限定的模拟器、评分器、两个基线与占位策略，确认这些文件没有网络、shell或子进程调用，也没有对外写入，再执行限定测试。没有读取或运行其他赛道。此结论只覆盖这些文件，不是整个ZIP或所有第三方资源的安全/许可认证。

以上是基于代码结构、执行规模与实跑表现的评审判断，不是统计难度百分位或独立模型能力测量。未执行高难档，也未做显著性检验、置信区间或跨模型排名。原生成器单独调大n/m，并不自动实现宣传的到达分布变化、特殊长链或多步陷阱。

两题都是真正的开放策略优化：R3没有指定最优实验树，R4没有指定最优分派策略。物理约束与损失公式固定，策略、停止时机和调度方式可以不同。另一方面，默认生成器和seed一旦公开，硬编码全部抽样答案/未来表就能污染评估。新seed参数解决了轮次可配置性，但本地同进程Python仍可做堆栈窥探、读取内部文件或拒不返回；它不是不可信策略沙箱，也没有实现真正的逐回合隔离JSON运行器。正式赛事还需要父层隔离、时间限制与封存纪律。

## 信息边界核对

R3基线只读取公开模型、已执行history和剩余预算；不会接收真值或seed。当前假设包括最多两个故障，条件独立探针与重复新观测属于题面模型，并不是现实事故规律。

R4基线只读取当前obs；当前公开观测time=50的20个job没有未来release，模拟器每步也过滤release。生成器仅选取release不晚于当前任务的前置任务，因此deps不会提前泄漏未到达任务。公开观察没有未来停机、真实结束时间或完整未来表。修复前的引用别名会改变约束，修复后已隔离。相同场景的外源随机结果按测试/重复或任务/机器保持对应，减少不同策略的抽样不一致。

## 基线实跑与诚实性

两个baseline.py均逐字节保持原来源文件，没有为提高分数修改策略。R3是单步信息价值近似；R4是可见信息上的调度启发式。它们不是直接测量某个大模型作答的结果。对照在run_review.py明确定义：R3不做检查，按先验选期望损失最小的修复集合；R4按(release,id)排序、设备ID升序的可行FIFO。

R3基线平均loss=27.769444444444446、尾部loss=67.47555555555556、平均查询6.111111111111111、精确诊断率0.24444444444444444。精确诊断率只是诊断指标，不能代替按后果计损失的主目标。

R4基线平均loss=53.62919653544704、尾部loss=86.03055593766273、平均完成54.05/60；FIFO平均完成51.7/60。这里的FIFO是本审查明确列出的对照定义，不冒称其与未检查的其他脚本中的FIFO完全相同。 原包曾列出约92.50的FIFO损失，但没有完整对应policy和执行链时，本次不认定这个数已被复现。我们新建并公开定义的FIFO得到98.93476991953729；原baseline约60.10946841589019在原版与适配版保持等价。不能把两种FIFO数值差异归因于此次边界修复。对照策略身份、代码与运行参数必须对应，属于可复现性验收项。

完整输出分别保存在两题目录的review_original_metrics.json和review_adapted_metrics.json。R4另存review_seed_smoke.json，只验证新seed参数可用与相同seed可重放，不是隐藏泛化成绩。上述raw是统一父任务约定的100/(1+L/10)，scoring.quality_from_loss仍返回0..1质量，父适配器乘100；这两种尺度的相对归一化一致。所有invalid必须从最佳有效解分母中排除。


run_review.py可以加`--task R1`或`--task R2`限定原包内部ID。内部ID仅用于来源审计；参赛题面已使用统一R3/R4。题面导出使用各题PUBLIC_TASK.md+submission.py+public*.json，不复制基线、测试、评分器、seed或实跑真值。

## 迁移依赖清单

- organizer/r1.py、r2.py、scoring.py：无ROOT、tasks路径或动态读文件依赖，标准库纯模拟/评分函数，可直接迁移；未执行模块的__main__测试不影响导入。
- R3 evaluator签名：evaluate(policy, models=3, episodes=30, *, model_seed=41, episode_seed=90000)。每模型最多10000个episode，避免默认层级seed区间重叠；原调用兼容。
- R4 evaluator签名：evaluate(policy, episodes=20, *, seed_base=72000)。原调用兼容。
- 两个baseline.py与submission.py：无ROOT或数据文件加载路径依赖。
- review_selftest.py：以自身parents[2]为包根，读取organizer/r1.py、r2.py、scoring.py；迁移时父层需更新这3个审查辅助导入路径。
- run_review.py：同样以parents[2]为包根，读取tasks/R1_diagnosis、tasks/R2_dispatch，并在--original时从根imports/pro_v01/upstream/organizer/organizer读取已审查原件。它是内部审计辅助，不应导出给参赛者；题目正式judge不依赖它。
- PUBLIC_TASK.md：无基线算法、成绩、主办方实现或具体seed；仅给公开协议与评分公式。TASK.md包含主办方说明，供内部保留。
