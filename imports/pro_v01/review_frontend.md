# 前端题审查与适配记录

审查对象：只读 `upstream/organizer` 与 `upstream/contestant` 的事故控制台、离线排程题；修订先落在 `packs/pro_v01/tasks`，对外统一编号为 F3、F4。这里保留内部来源与审计记录，不把它们作为独立赛道。

## 结论

两题有真实难度。F3在50,000条动态数据、版本墓碑、虚拟化、对象身份、URL与CSV导出之间设置交叉约束；F4要求多窗口字段合并、旧编辑器冲突、补偿式撤销、永久删除、离线与导入语义一致。它们显著区别于静态页面生成。不过，原裁判是作者DOM专用的 smoke 脚本，原13/13与16/16结果来自about:blank上的显式内存适配器，不能直接当作新比赛成绩，也不能直接评另一套合法UI。

## 对照题面

逐项 diff 主办方/参赛方 TASK.md：主办方多了作者基线说明、原环境自述及历史验证范围；核心用户流程、事件语义、高难档与设计目标相同。没有在这次对照中发现只告诉主办方的额外硬评分要求。

真正的公平性风险在测试实现：原脚本定位 `.row`、`.task`、`#detail-title`、`#lane-2`，并依赖作者默认数据文案。这些细节未构成参赛者公共契约。修订明确保留它们为**基线回归smoke**；每题另附 PUBLIC_TASK.md 和 semantic-rubric.md，列出可访问语义、数据接口与必要类型约定。正式多实现裁判仍需由主办方提供控件映射或新的语义驱动runner。

## 已修复的具体问题

### F3 事故控制台

- 原版只验 id/rev，高版本的非法日期、严重度或对象标题能进入状态；`toISOString()`随后可能抛错。新增整批类型检查，非法load不会先清空原数据。
- 原save()对localStorage写入不捕获，配额/权限错误会中断选择与筛选。现在保留本页状态与URL并显示未持久化提示。
- URL枚举及恢复的存储结构缺少检查，已限制到公开枚举；记录、暂停队列接收副本，避免调用者之后修改对象改变内部内容。
- 原版本墓碑的方向正确，保留并加逻辑回放；未改成全局不可复活墓碑，因为该题允许更高版本完整记录按协议重新出现。

### F4 离线排程

- 父代理原生HTTP抽测在本次in-app Browser surface遇到原生confirm的CDP操作超时；为兼容该surface，改为可访问HTML dialog，保留明确取消/确认删除。未宣称所有浏览器原生confirm有缺陷。

- 原validEvent不校验字段值类型，`lane:"1"`等可让任务计数存在、三个资源列却都不显示。新增文本/整数/范围/字段名验证。
- 同一导入批次内的同ID异内容原本可能先写第一条再抛错。现在先校验整个批次及已有状态，出错不部分导入。
- 原JSON.stringify内容比较误把对象键序变化当内容冲突；改为规范化键序比较。导出返回独立深拷贝，防止外部修改导出对象反向改内部状态。
- actor原从sessionStorage继承，由opener打开/复制的窗口可能共用身份；改为每个document新actor，旧outbox仍保留原事件身份。
- 原字符串localeCompare及拼接stamp有环境差异/分隔符歧义；改为确定的UTF-16比较与JSON数组stamp。
- 删除检查原在scan前，可能错过尚未接收的远端删除；现扫描后再次检查，拒绝陈旧写入。墓碑之后到达时，还会替换旧成功消息为“任务已删除，未保存旧编辑内容”。真正断联时不能凭空知道远端删除；离线patch可先保留，恢复合并后墓碑必须获胜。
- 共享存储写失败原会在已接收内存事件后抛出并中断；现在保留outbox、尝试本窗口持久化并明确警示，全部存储失败仍保留内存以便导出。
- 部分字段创建的任务采用可见缺省字段与时段冲突状态，不静默隐藏。跨窗口同字段改写历史在卡片可见；这不是完整因果并发识别。
- 原新建任务撤销会把整数补偿为空字符串。创建现在明确不进入字段撤销栈；字段编辑仍可补偿撤销，删除仍不可逆。此边界已向所有参赛者公开。

## 裁判与证据修订

- native runner增加明确环境标签、`raw_score:null`、`human_visual_score:null`及“基线专用smoke”范围；输出放到 `results/native_http/`。
- memory runner输出放到 `results/memory_adapter/`，避免覆盖同名原生结果；适配器不再吞掉远端事件投递异常，并新增相应检查。
- 两个runner同时捕获第二页的pageerror，避免只检查主页便宣布“双页无异常”。
- about:blank适配器模拟localStorage、sessionStorage、URL导航与Blob下载，主动改写源码中的location访问；它能验证部分DOM与合并逻辑，但不验证真实origin限制、浏览器下载、真实会话继承、关闭恢复或存储竞态。
- 原报告12次200事件批次的双requestAnimationFrame耗时，不等于持续200条/秒的长时间性能；慢CPU和压力档仍需另外测量。
