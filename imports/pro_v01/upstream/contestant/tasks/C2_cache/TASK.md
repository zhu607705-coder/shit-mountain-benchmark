# C2 · 缓存命中 99%，发布产物却是旧的


## 参赛题面

一个遗留增量构建器速度很快，却会偶发使用错误产物。修复 starter，使同一个 root/spec/env 在任意合法缓存历史之后，都产生与无缓存解释器相同的目标字节。架构与缓存格式可以完全重写。


## 输入与 DSL

Builder(root, cache).build(spec, target, env) -> bytes。

spec.nodes 是命名 DAG。source 节点从 root 内相对路径读取字节。其他节点按 deps 的原始顺序获取依赖，separator 是 UTF-8字符串。concat 按 separator 拼接；upper 先按 UTF-8解码再转大写；reverse 按 Unicode码点反转；sha256 对拼接字节取十六进制 ASCII摘要；envcat 在拼接结果前加入 prefix，然后按 env 名单顺序追加环境值（缺失为空字符串）。

只解析目标可达子图，无关坏节点不能影响目标。可达循环报告 CycleError。不存在的源文件报告 BuildError。符号链接可以指向 root 内文件，但不得读取 root 外源文件。构建时 root 的内容保持稳定，测试在两次 build 之间修改文件；没有声明任意写入期间的原子多文件快照能力。


## 必须处理的历史变化

文件内容变了，大小和 mtime 没变；源文件删除；不同目录下同名文件；配方与依赖顺序变化；传递依赖变化；环境变量变化；缓存跨两个根目录共用；多个进程同时发布同一个缓存结果；缓存条目不完整。未声明的环境变量不应影响结果。


## 高难档（未执行）

5,000 节点、共享依赖、数百 MiB 输入、多个根目录、热冷交替构建和多个工作进程。追加一轮已公布类型的重命名/环境变更任务。比较冷构建、无变化构建、局部变化构建、内存、缓存膨胀和失效范围。不能通过每次删除缓存或永远全量重建同时拿到性能高分。


## 判分原则

过期输出、越界读取和依赖顺序错误是关键问题。已修正确性后才比较效率。无缓存解释器是行为参考，不是唯一实现；缓存设计、任务并行策略和数据布局均开放。
