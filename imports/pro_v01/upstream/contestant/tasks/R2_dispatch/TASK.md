# R2 · 越救越堵的在线调度中心


## 参赛题面

你管理异构工作站。任务逐步到达，有前置依赖、截止时间、优先级、可使用设备、功率需求及工艺类别。切换类别需要准备时间。设备可能突然停机，正在处理的任务会失去进度并等待重新开始。真实处理时长在开工前存在不确定性。

每个离散时刻，你只能看到当前已经到达的任务、完成记录、设备可用状态、历史工艺类别及剩余功率。返回 [{"job": "J003", "machine": 2}, ...]，也可以返回 [] 等待。不能分配尚未到达的任务、占用中的设备或未满足前置条件的任务；不能超功率。未来任务、真实未来加工时间和故障时刻不公开。


## v0.1 精确定义

60 个任务、6 台设备、300 个离散时间单位。功率容量为 10。加工时间等于公开名义时长 × 设备倍率 × 隐藏实现倍率，再向上取整；同一设备工艺类别不同则增加 3 个时间单位。隐藏倍率范围为 0.75–1.25。同一任务在同一设备的实现倍率固定，防止靠重启重抽好运气。任务不可暂停，故障后从零开始。

到期未完成的任务不能通过丢弃来提升评分。unfinished 的虚拟完成时间取 H+180，并另加未完成权重惩罚。

loss = 加权总迟延 / 总权重 + 40 × 未完成权重 / 总权重 + 0.002 × 功率时间总量 + 0.25 × max(0,开工次数-任务数)。


## 难点

最紧迫任务可能堵住某条关键依赖链；最快设备可能是后续任务唯一可用的设备；提前满载可能增加换型和故障损失。你需要决定立即执行、保留容量、选择设备和如何恢复，不存在固定的唯一排列。


## 高难档（未执行）

240 个任务、12–18 台设备，更长运行时间；跨阶段到达分布变化、资源拥塞、两个设备同时故障、稀缺设备和长依赖链。规格与分布支持范围在赛前公布。可比较滚动搜索、有限前瞻模拟、价值函数和不同分派规则。允许等待，但不允许偷看未来。
