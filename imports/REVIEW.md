# 题库适配、契约与难度审查

当前题库已合并为 R1–R4、C1–C4、F1–F4，共 12 题。同一注册表、导出/导入入口、评测结果格式和相对分规则，不按生成来源另设排行榜。来源只用于维护者追溯。

## 来源、权限与参赛隔离

- 用户交付的两个 ZIP 的 SHA256 与文件数保存在 `pro_v01/provenance.json`。安全展开前检查成员路径、链接类型和总大小，原文件保持原样。
- 主办方原包 56 文件、参赛原包 21 文件；主办方自带清单的 55 项哈希全部吻合。原参赛包没有 baseline、oracle、组织者目录或结果文件；两包的公开起点有 13 个文件逐字节相同，8 个文档不同，逐题复核差异主要为作者说明和评测边界。
- 所有对外题面现使用统一 `PROMPT.md`，新增公开契约从原参赛题面派生；基线算法、作者成绩和裁判实现不进入参赛导出。
- 未发现包中真实 API 密钥、私钥、外部网络上传或第三方图像下载逻辑；这是针对已读代码和文件的有限审查，不是对任意未知提交的安全认证。
- 材料没有完整再分发许可证文件。保留作者来源声明与参考链接，不擅自授予 MIT/Apache 等许可；本次进入用户授权的私有仓库，没有据此宣布完成开源权属认证。参考论文链接不等于代码许可。
- 同进程 Python 评测仍只适合可信本地实现。输入复制解决共享对象污染，不能替代隔离执行、超时、资源限制或阻止策略查看宿主内存。

## 难度判断与入库状态

下列是基于结构和已运行规模的审查判断，不是多模型通过率测量。

| 题目 | 目前难度来源 | 本次能支持的判断 |
|---|---|---|
| R1/R2 | 组合规划、成本风险、依赖与资源权衡 | 有开放优化空间，启发式基线非最优；未做模型难度校准 |
| R3 | 10组件/56假设/20探针、有限预算与停止策略 | 当前中等；专门多步互补信息陷阱未校准 |
| R4 | 60任务/6设备、只能看已到达任务、停机重调度 | 当前中等偏高；240任务/18设备高压档未执行 |
| C1/C2 | 实际服务、持久化、worker、路径/迁移/恢复/隔离 | 综合工程修复题，分别7和11类环境；不是大型生产仓库 |
| C3/C4 | 日志耐久性与缓存语义的组合故障 | 有价值的机制专项题；12/17组检查不代表十万键/5000节点压力通过 |
| F1/F2 | 信息密度、状态身份、离线持久化与冲突决策 | 真实浏览器核心流和双窗口路径已抽测；完整UI评分待执行 |
| F3/F4 | 50k列表/版本墓碑，以及多窗口字段合并和补偿撤销 | 状态逻辑与部分原生HTTP流程已测；长压、IME、3–5窗口及完整无障碍仍待测 |

题面中的高难目标不会自动加入当前通过声明。C2 自测质量剩余10分、C3/C4正式性能映射、全部前端独立盲评未完成时，完整质量分保持 null。统一题库不等于把所有不同证据强度强行抹平。
