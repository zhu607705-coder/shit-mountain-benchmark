# 抽题舞台重做

用户明确否定表格式挑战控制台，指定超现代结构艺术、波普艺术、真实抽题过程、鼠标响应，以及随题目改变的刀片状 HTML 切面。当前工作是按这一授权直接重做入口，保持既有封存、独立检验和计分链路。

## 视觉与交互

- 第一屏只有一个抽题舞台：悬浮签卡、巨幅编号/字形与有层次的刀片切面。黑、暖白和荧光黄形成主对比，少量其他高饱和色用于题目身份。
- 外围结构使用不等角、遮挡、出血和不同深度，不用十二张矩形卡片占据主画面。R/C/F 对应不同几何构成；不同题目继续改变切面参数。
- 鼠标同时影响签卡与外围切面，使用有界变换与 requestAnimationFrame。减少动态效果偏好和触屏采用稳定构图，控件不追逐鼠标。
- 核心操作是方向、难度、“抽一道”。抽取经过蓄势/洗牌、切面变换和真实结果揭晓；服务器返回结果以前不得伪造已抽中的题目。
- 手动选题、历史场次、任务说明、答案表单和成绩进入次级菜单或工作面板。揭晓后点击“开始这题”进入完整答题流程。必要错误、待评和原分/相对分仍清晰显示。

## 接口与归属

主 Agent 负责服务端随机题池、冻结元数据、HTTP 回归与最终浏览器验证；前端 Agent 独占 arena/web 页面、样式、行为及 motion.js；独立评审只读检查构图和交互质量。

`POST /api/draw` 新增 `task_id=random` 与 `track=all|R|C|F`。服务器用 secrets.choice 在合法题池中选择题目，结果与已存在的 scope/seed 承诺一起保存。实际 task_id 继续驱动导出和判分；指定题目的原 API 兼容。前端动画不参与题目选择，也不决定分数。

## 参考与实现边界

- [Pentagram / Shakespeare In The Park 2016](https://www.pentagram.com/work/shakespeare-in-the-park-2016)：黑底、漫画轮廓与大字的结构。
- [GSAP 官方 Showcase](https://gsap.com/showcase/)：空间对象与互动布局参考。
- [Randomize & Focus](https://madewithgsap.com/effects/tutorial025)：公开介绍中的鼠标邻近卡片响应；不复制其付费实现。
- 功能图标继续采用已锁定版本的 Lucide。参考页面作品不作为本站素材复制，页面几何与运动代码独立实现；运行时保持离线可用。

验收需要真实浏览器的首屏视觉、鼠标前后构图、随机结果与服务器匹配、抽题失败恢复、键盘/窄屏、封存检验全链路，以及无控制台错误的证据。完成后更新公开仓库与正式 v0.2 包。
