# F3 · 首屏很漂亮，五万条实时记录一来就崩


## 参赛题面

把 starter.html 修成可以实际使用的事故工作台。初始数据 50,000 条，持续更新、乱序、重复和删除同时存在。用户在筛选、滚动或打开详情时，不能看到错误对象。布局、视觉风格和框架可以重做，不要求复刻 baseline。


## 公开数据接口

window.bench.load(records) 替换完整数据；window.bench.ingest(events) 注入消息。单条记录含 id、非负整数 rev、title、service、severity(0–3)、status(open/resolved)、updated(毫秒时间戳)。删除事件含 id、rev、deleted:true。id+rev 对应唯一内容。仅接受更高版本；删除的版本信息不能随行一起丢失，否则迟到消息会使其复活。


## 用户必须完成的流程

搜索标题/服务，按严重程度和状态筛选；按更新时间降序，同时间按 ID 稳定排序；选择一条记录，在排序和更新后保持该 ID 的详情；键盘选择记录；复制/分享或刷新后恢复 URL 中的筛选状态；暂停更新，恢复后正确应用积压；导出当前全部筛选结果，而不只是可见行。CSV 文本需要转义引号与换行，并中和以 =、+、-、@、tab、CR 开头的单元格公式风险。标题包含 HTML 时按文本显示。

采用虚拟列表或其他可控 DOM方案，不能为五万条记录永久创建五万个完整交互节点。320/768/1440 px 下可以操作。关键内容不得只靠颜色表达。除确有二维数据需求的局部区域外，页面不应发生横向溢出。


## 高难档（未执行）

持续 200 条/秒、1,000 条突发、长时间暂停、筛选时删除选中记录、300–2,000字符标题、中文输入法组合事件、200%文本缩放、慢CPU、缩小窗口中继续操作。事件顺序和时间由评测器控制，不能依据已知 ID 特判。


## 设计评分

用同一份未知内容完成指定工作流后做匿名设计评价，考查信息层级、密度控制、排版、响应状态、可操作性。不是只给静态首屏投票。基线截图不是像素答案。正式测试也不应锁定 baseline 的 class 名或内部 DOM。

## 本次适配补充公开契约（F3，2026-09-26）

本节是正式发布前的公开修订，适用于所有参赛者；未经本轮复核的历史结果不计入本轮成绩。布局和技术栈继续开放。

- 输入接口保留 `window.bench.load(records)` 与 `window.bench.ingest(events)`。记录 `id` 为非空字符串、`rev` 为非负安全整数；普通记录 `title/service` 为字符串、`severity` 为0–3整数、`status` 为 open/resolved、`updated` 为可表示有效日期的安全整数毫秒时间戳。删除记录使用布尔值 `deleted:true`；字符串 `"true"` 不等价。
- 输入不是数组、缺字段、字段类型错误或日期越界时，应拒绝整批并保留已有状态，给出可理解错误；`load` 不能先清空数据再发现输入非法。接口可返回失败或抛出可处理的业务错误，不得留下部分更新。
- 相同 id+rev 的内容唯一由数据源保证；比较版本不能受消息到达顺序影响。删除保留版本号，低版本补丁不能复活；更高版本的完整记录仍按公开版本规则处理。
- 浏览器存储写入失败时，筛选与选择仍可在本页使用，必须明确说明未持久化。非法存储和无效 URL 枚举不能让界面崩溃。URL 保存的是筛选和选择，不要求保存整个合成数据集。
- 评测器只能要求上述数据接口与可访问语义，不能要求 `.row`、`#detail-title` 等作者内部结构。测试用关键词和 ID 可变化，不以默认示例恰好有几条匹配作为额外隐藏要求。

公开语义场景：载入50,000条→关键词/严重程度/状态组合筛选→按ID选择→注入更高/更低版本→暂停/恢复→删除→导出完整筛选结果→刷新恢复筛选。额外执行非法批次、HTML字面量、CSV六类公式前缀、键盘与窄屏。高难档负载与输入法测试若正式计分，主办方须事先公布负载和预算；不得把未运行的档位算作已通过。
