# F3 语义评测映射

正式权重与资格门槛以统一比赛规则为准；本文件不另增隐藏门槛。参赛者可重新布局和改变框架；题面规定的事件接口与可访问语义必须保留。

| 公开任务 | 可复放断言 | 不应要求 |
|---|---|---|
| 完整载入与筛选 | 载入已知50,000条，组合关键词/级别/状态后，数据源独立计算的ID集合与UI/导出一致 | 默认文案恰好等于某段固定文字 |
| 版本与对象身份 | 选中指定ID，注入较新/重复/迟到版本，详情始终对应该ID和最高版本；删除后迟到版本不复活 | `.row`、`#detail-title`、固定行高 |
| 暂停恢复 | 暂停后数据保持，恢复后应用积压并遵守每条记录版本 | 某种内部队列或框架 |
| 导出 | 原生浏览器实际下载CSV，核对完整筛选结果、引号/换行、六类公式前缀 | 只检查Blob对象已创建 |
| URL与持久化 | 原生HTTP origin中更新筛选、刷新、地址栏恢复；存储失败反馈明确且操作可继续 | 仅在内存伪造history通过 |
| 输入错误 | 非法批次拒绝且已有数据不变；无效URL和损坏本机状态不崩溃 | 用作者内部Map作为唯一验收来源 |
| 键盘与响应式 | 纯键盘筛选/选择/读详情/导出；320/768/1440px核心操作可达 | 像素匹配作者截图 |

作者控件的语义示例为“搜索标题或服务”“严重程度”“状态”“暂停更新/恢复更新”“导出筛选结果”；其他清楚等价命名可以通过提交的控件映射适配。行应向可访问树暴露稳定记录ID与标题。

`organizer/check_frontend*.py` 仍是作者基线专用 smoke runner。它绑定内部DOM，仅能用于该实现回归，不能直接据此判另一个合法UI不合格。两个runner分别输出 native_http 与 memory_adapter 结果；旧结果不得覆盖成新的原生验证声明。盲评独立进行，未执行保持 null。
