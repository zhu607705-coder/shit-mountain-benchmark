# F1 评分与可复放场景

原始质量 `Q = 功能 60 + 可访问/响应式 20 + 盲评 20`。每个公开机器场景 5 分，按整项通过/失败；不得根据“有这个按钮”给分。所有自动化结果必须有观察或断言，未测为 `pending`，不能当作通过。

每次在全新 origin/storage 状态启动，使用固定 `data.json`。建议 5 次重复计性能中位数并同时报告设备、浏览器、屏幕、冷启动/热启动；性能不与另外一台机器直接比较。

## 可访问与响应式 20 分

| ID | 操作与必须满足的断言 |
|---|---|
| A01 | 只用键盘完成搜索、筛选、选事件、读详情和确认，焦点清晰，列表身份向辅助技术暴露，焦点不消失或被困住。 |
| A02 | 在 1440×1000、768×1024、390×844、360×800 检查；页面无非必要横向溢出，核心文字不互相遮挡，窄屏所有操作可达。 |
| A03 | 用可访问性树检查名称、角色、选中状态和状态播报；严重级别不只用颜色编码；主要文字对比度满足 WCAG AA。需报告实际工具/人工检查证据。 |
| A04 | 200% 缩放与长中文标题仍可完成核心场景；触屏目标和滚动可靠；偏好减少运动时无必要动画障碍。 |

## 盲评 20 分

只有功能至少 55/60，且没有脚本执行、静默丢数据或事件身份错配等关键失败，才进入盲评。评审不能看到模型名字，每个候选随机排序、至少 3 位评审。

评审用相同任务：“找出注入事故的上游事件，确认入口告警，交接给另一位值班者。”记录完成时间、误操作、是否解释得出证据链，再比较信息层级（5）、高密度下可读性（5）、跨设备任务效率（5）、视觉一致性与克制（5）。20 分依据任务过程和成对偏好得出，不按是否像参考截图给分。

`human_visual_score=null` 表示未盲评；此时 `raw_score=null`。运行证明、机器场景通过数与盲评分必须分开。

比赛内相对分应由主办方统一计算：在通过资格门槛且完成人工评分的提交中，最好 `Q` 记满分，其他按 `100 × Q / Q_best`。若没有合格提交或 Q_best=0，本轮不产生冠军分。任何模型即使相对分 100，也不代表绝对质量完美。
