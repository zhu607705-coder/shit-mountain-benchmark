# 自家基线：NIGHT WATCH

`baseline.html` 是完全自包含页面；可直接打开，也推荐用 HTTP 运行以验证 URL、剪贴板与浏览器持久化。外部网络关闭仍可工作。`baseline.template.html` 是易读源码，运行上级 `build_frontend.py` 会把固定 `data.json` 嵌入成最终页面。

设计采用深色工业值班台：事件流、当前证据、因果路径三块并置，P1/P2/P3 始终含文本。移动端顺序变为列表 → 详情 → 证据。列表行高固定 88 px，按可视区域加 3 行 overscan；ID 是所有选择与确认操作的身份。

## 已实现

- 完整 10,000 条数据与字面搜索、服务/严重程度/确认状态交集筛选。
- 虚拟列表、方向键/Home/End、选中事件的稳定 ID。
- 查询参数恢复筛选和选中项，popstate 恢复，空结果状态。
- localStorage 每事件独立键持久化确认/撤销、失败提示、跨窗口 storage 刷新；不同事件更新不再覆写同一个集合。
- 已知注入关系的上下游跳转、长文本、HTML 转义。
- 窄屏重排、原生表单标签、焦点样式、状态播报、无外部字体/图标/脚本依赖。

## 真实边界

- F08 的持久化机制已改为每事件独立键；不同 ID 的写入互不覆盖，同一事件相反操作按最后一次键写入决定。完整双窗口重复场景仍应独立实测，不能只凭实现推断通过。旧版整集合只读兼容，新的状态逐事件覆盖。
- 没有真实流式后端、服务器分页或生产事故接入；“已知因果”只适用于固定仿真。
- 固定行高使列表标题截断，完整文字在详情；剪贴板受浏览器权限影响，有手动地址栏回退。
- 每次输入对一万条做同步搜索，在极慢设备上的响应延迟需要实测；没有宣称任何性能毫秒阈值。
- 原生 `role=listbox` 单焦点键盘模式已实现；屏幕阅读器、触屏与 WCAG 对比度需独立实测，不能只依据源码认定通过。

## 本次证据

运行过的验证与待验证项以 `verification.json` 和父级浏览器报告为准。JS 语法检查不等于浏览器功能验收。未进行外观盲评，`human_visual_score=null`；不自称 100 分。

公开检测入口 `window.BENCHMARK` 只用于读取状态，不参与 UI 功能：`total`、`state()`、`visibleIds()`、`acknowledged()`、`renderedCount()`。自动化应优先通过可访问名称操作，最后用此入口或独立数据运算核对结果。
