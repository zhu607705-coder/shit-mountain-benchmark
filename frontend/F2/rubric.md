# F2 评分与可复放场景

原始质量 `Q = 功能 60 + 可访问/响应式 20 + 盲评 20`。每个公开机器场景 5 分。没有独立实测的场景必须列入 `pending`；只看按钮或源码不等于测试通过。

测试前清空当前 origin 的 `field-notes-v1` 存储，刷新打开；测试之间按需恢复。必须保存浏览器 console、关键截图和状态断言。

## 功能 60 分

| ID | 操作与必须满足的断言 |
|---|---|
| F01 | 12 个任务与数据源完全一致。初始存在 5 条约束问题：T04←T03、T07←T06、T09←T08 三条依赖冲突，以及 T06/T07、T04/T11 两条资源重叠。不同资源同时运行不得误报。评委应从 data.json 独立计算并核对。 |
| F02 | 编辑 T04 开始时间12:00、时长60、资源HPLC、备注中文长句；保存后列表、详情、时间线一致，ID 与其他字段不变。 |
| F03 | 先修改时间再改备注，撤销两次、重做两次；每步精确还原，重载后仍保持最后状态，不用“保存失败”掩盖错误。 |
| F04 | 输入未知依赖 T99、自依赖 T04、以及 T01→T02→T01 的环；拦截并保留原数据，错误可见，取消编辑不修改任务。 |
| F05 | 调整同一资源任务到首尾相接，再制造 1 分钟重叠；前者通过，后者出现准确冲突；窗口外时间不可保存。 |
| F06 | 切离线，编辑 T05 备注并改期，撤销/重做，再重载；离线状态、任务与未同步标识持久化；同步不可误显示成功。 |
| F07 | 全新状态“注入远端更新”；T05 start 变255、note 变远端文本，非冲突自动合并。先在本机仅改 title 再注入，title 保留，其他更新合并。 |
| F08 | 本机先把 T05 start 从230改到240，再注入远端start255；产生开始时间字段冲突，能显式保留本机或远端；选择本机则240不变，选择远端则255，之后同步与刷新一致。 |
| F09 | F08 冲突先“稍后处理”，再把本机start改为270，重开冲突选择本机；必须保留270而不是旧快照240。刷新后未解决冲突仍可处理。 |
| F10 | 两个窗口同时分别改 T03.note 与 T09.start；刷新后两项均保留，或在任何可能丢弃前给出可恢复的显式冲突处理。仅显示“另一个窗口写入”但随后覆盖，不通过。 |
| F11 | 保存时注入 localStorage.setItem 抛错；不能显示保存成功；仍能导出 JSON，下载内容包含未保存修改和未解决冲突；不以“发起下载”冒充下载文件已验收。 |
| F12 | 循环20次筛选、改期、撤销、编辑、远端注入与合并；不能丢任务/产生未知ID/NaN时间，列表与时间线始终一致。 |

## 可访问与响应式 20 分

| ID | 操作与必须满足的断言 |
|---|---|
| A01 | 纯键盘完成任务选择→打开编辑→错误纠正→保存→撤销→合并，所有控件名称明确，dialog 焦点不会落到不可操作背景。 |
| A02 | 1440×1000、768×1024、390×844、360×800均可完成核心流程；只允许时间线/数据表局部横向滚动，页面宽度不溢出。 |
| A03 | 可访问树、焦点、主要文字对比度、状态播报与错误关联经过独立检查；约束状态不依赖颜色识别。 |
| A04 | 200%缩放、触屏、长任务名/长备注下核心操作可达；无需拖拽，弹窗内容可滚动，按钮不会被键盘或视口挡住。 |

## 盲评 20 分

功能至少55/60且没有静默丢失修改、错误宣称已同步、依赖环进入有效排程等关键失败才进入盲评。匿名随机排序，至少3位评审；按统一场景修复 T04/T11 冲突、离线调整 T05、合并远端变更。

比较排程关系的可理解性（5）、冲突决策的清楚程度（5）、桌面与移动操作效率（5）、视觉一致性与阅读舒适度（5），同时记录完成时间与误操作。拖拽、甘特图或卡片数量本身不加分；没有唯一最佳布局。

未盲评则 `human_visual_score=null, raw_score=null`。赛内相对分仅对已合格并完成人工评分的提交计算 `100 × Q / Q_best`；没有合格提交或Q_best=0时不计冠军分。相对满分与绝对正确率分开公布。
