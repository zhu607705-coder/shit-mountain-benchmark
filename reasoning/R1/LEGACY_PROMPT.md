# R1：风暴之后，先修哪里？——相关扰动下的鲁棒资源调度

## 任务

你负责一个完全虚构的设施修复系统。4 个地区、8 条修复链共 48 项任务争用 3 类资源和 3 个作业区。任务存在先后依赖、跨链依赖、释放时间、交付期限和 3 种施工模式；多种扰动会同时延长工期、减少资源可用量、降低交付质量。你要提交一份可执行的任务选择与优先级计划，使平均收益、较差情景收益和地区公平性尽可能高，同时控制预算。

全部数据均为**程序生成的合成数据**，不对应真实灾害、真实设施或实测效果。`input.json` 是完整公开优化实例；裁判不需要预先知道最优方案，也没有标准任务顺序。允许你使用任意求解方法，但提交物必须符合下面的 JSON 契约。

## 已知输入和决策边界

- 48 项任务，每项有 `value`、`region`、`zone`、`release`、`deadline`、`dependencies`、`mandatory` 和 3 个 `modes`。
- 每个模式给出固定 `cost`、基础 `duration`、3 维资源需求 `resources`、基础交付质量 `quality`。
- 离散时间轴为 0–71，工期使用半开区间 `[start, end)`，最后允许完成时间为 72。
- 预算为 450，所有选中任务在规划时付费，无法排入某个情景的任务也不退费。
- 24 个公开情景提供逐时刻资源容量、逐任务工期乘数与质量乘数。该实例情景权重均为 1；裁判支持非均等权重。
- 同一作业区同一时刻最多执行一项任务；任务执行期间不可抢占。
- `mandatory=true` 的含义是**必须纳入提交计划**，并不要求它在每个情景里必然完成。

本题优化的是“任务选择、模式选择、全局优先级”，不直接提交开工时间。裁判负责把你的计划转换为每个情景中的排程。所有情景从开始就是已知的，不能把这套公开实例的结果称为隐藏测试表现。

## 提交协议

输出 UTF-8 JSON 文件，只允许两个顶层字段：

```json
{
  "format_version": 1,
  "plan": [
    {"task": "P1T1", "mode": "standard"},
    {"task": "P2T1", "mode": "careful"}
  ]
}
```

上例只示意结构，并非可行的完整提交。`plan` 的顺序就是分配排程的优先级。

硬约束：

1. 每个条目只能有 `task` 和 `mode` 两个字符串字段；任务与模式必须存在。
2. 同一任务最多出现一次；所有必选任务必须出现。
3. 选中任务的每个依赖也必须被选中，并出现在它之前。任务不能绕过依赖。
4. 模式成本之和不得超过预算。
5. `format_version` 必须是整数 1；布尔值、额外字段、重复 JSON 键、NaN 和 Infinity 均不接受。

## 每个情景如何回放

裁判按 `plan` 顺序逐个分配任务，已分配的时间区间不再调整。

1. 实际工期为 `ceil(mode.duration × scenario.duration_factor[task])`。
2. 若任一前置任务无法排程，该任务也无法排程。
3. 否则，从“释放时间与所有前置任务完成时间中的最大值”开始，寻找最早的连续可用区间。区间内必须同时满足三个资源容量和作业区互斥，且结束时间不超过 72。
4. 找不到区间就记为 `unscheduled`，本情景收益为 0。后续任务仍继续尝试排程。
5. 能排入则计算质量：`q = 模式质量 × 情景质量乘数 × min(各直接前置任务的有效质量)`；没有前置任务时最后一项为 1。
6. 收益为 `value × q × max(0, 1 − max(0, end − deadline)/18)`。期限属于软约束；超过期限 18 个时间单位后收益归零。即使收益归零，已执行任务仍占用资源。

这里的 `min` 传播是本合成系统明确规定的质量模型，不是现实工程定律。

## 评分

某地区覆盖率 = 该地区已获收益 / 该地区全部原始任务价值；情景总覆盖率 = 全部已获收益 / 全部原始任务价值。公共实例的全部原始价值为 2903。

- `M`：按情景权重加权的平均总覆盖率。
- `T`：总覆盖率最低的 20% 情景概率质量的平均值；边界权重允许按比例截取。
- `F`：每个情景先取 4 个地区覆盖率的最小值，再按情景权重求平均。
- `C`：计划总成本。

`raw_score = max(0, 1000 × (0.55M + 0.25T + 0.20F) − 50 × C/450)`

原始分越高越好。非法提交 `valid=false`、`feasible=false`、`raw_score=0`；可合法回放的计划二者为 true，即使一些情景中出现 `unscheduled`。所以 `feasible` 表示**计划满足提交与预算契约**，不表示所有选中任务在所有情景完成。

评测示例：

```bash
python3 judge.py --input input.json --submission your_output.json
```

裁判输出原始分、各分项、逐情景结果以及逐任务排程，便于复核。赛会层面的“当轮最佳解记满分”归一化在本题外完成；本题不会把自带基线记为 100 分。

## 为什么困难

增加任务可能挤占关键时段并降低别的任务收益；最快模式会增加资源与成本需求并降低质量；只追平均收益可能在相关故障情景中崩溃；只抢高价值链可能拉低最差地区覆盖率。跨链依赖与质量传播又使后期任务的名义价值不等于边际价值。你的任务是找到这些冲突下更好的计划，而不是解释一段固定答案。
