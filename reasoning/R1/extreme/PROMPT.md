# R1：不能撤回的扩容，与不断到来的修复合同

这是统一题库 R1 的 `extreme` 实例规格，目标仍是可执行的高收益、低风险资源调度。**full 实际生成 576 项任务，旧实例为 48 项，数量为 12 倍。** `smoke` 使用相同规则的 48 项实例，只用于接口回归。所有实例均为合成系统。

任务从一次性选顺序变为在线决策：合同分批出现，资源投资不可撤回，正在施工的合同可以取消但无法收回全部花费；较差的上游交付质量还会沿依赖链向后传播。优化方案不预设，不保证存在唯一最优解。

## 可见信息与因果规则

full 为 24 条交错依赖链、24 批合同、6 个地区和 240 个时刻，每批相隔 6 时刻到达。smoke 为 6 条链、8 批合同、64 时刻，每批相隔 4 时刻。到达合同给出 `id/region/release/deadline/value/dependencies/modes`。`modes` 中有 `standard/fast/careful` 三种方案，包含工期、成本、三维资源和质量；各模式必须以实际输入为准。

每个时刻按以下顺序处理：结算刚完成的工作；公布当前天气和新合同；处理扩容、取消、开工；进入下一时刻。终点只结算，不接收新开工。

- 未来合同、未来天气和生成种子不进入策略观测。依赖只指向此前已到达的合同；可见任务包括已完成、执行中和等待中的任务。
- 每 8 时刻天气保持一致，下一段以 0.28 概率为风暴。风暴使各资源容量减少 3，最低为 1；在风暴中开工的工期乘 1.5 后向上取整，质量乘 0.91。开工时确定工期及天气质量，后续天气不改写它们。
- full 基础资源容量为 `[16,13,12]`，初始预算为 `round(576×7.2)`；smoke 为 `[8,7,6]`，初始预算为 `round(48×7.2)`。
- 对任一资源扩容，full 花费 65 并永久增加 4，smoke 花费 22 并增加 2；每个资源最多扩容 3 次。投资会挤占合同预算，不能出售或退款。
- 天气下降时，已开工任务继续执行，允许暂时超过新容量；剩余容量按 `max(0, 当前容量−占用)` 计算，新开工仍不得超出剩余资源。
- 开工必须满足已到达、等待中、所有依赖已完成、预算与资源足够；工期不可抢占，资源占到完成。
- 取消执行中任务会丢弃全部进度，退还 `floor(原成本×0.5×剩余工期/原工期)`，任务回到等待。重新开工重新付款，但天气取当前状态。
- 完成质量 = 模式质量 × 开工天气质量 × 所有直接前置任务完成质量的最小值。没有前置时最后一项为 1。
- 收益 = `value×完成质量×max(0,1−max(0,完成时间−deadline)/24)`。迟到后仍须花费资源和成本，不能把它从总需求中删除。

## 交互与提交

提交 `policy.py` 可执行 Python 程序：从 stdin 每行读取一个 JSON 观测，向 stdout 每行写出一个 JSON 动作，并立即 flush。进程在同一评测中持续运行；`reset=true` 表示开始独立场景，应清理上场景状态。调试文字写 stderr。

观测字段为 `task/reset/episode/time/horizon/jobs/completed/running/budget/free_resources/weather/investments/investment_cost/investment_gain/maximum_investments`。`completed` 提供时间、交付质量、收益；`running` 提供已经发生的开工时间、成本、资源、质量，不提供任何未来任务表。

动作必须**恰好**为：

```json
{"invest": [0], "cancel": [], "start": [{"job": "J0000", "mode": "standard"}]}
```

`invest` 是资源索引数组，可同一时刻多次投资同类资源；每项须为整数 0–2。`cancel` 是无重复的执行中任务 ID 数组。`start` 中每项只能含字符串 `job/mode`，同一任务只能启动一次。三个动作组依次执行，组内按数组顺序执行，后续动作使用先前动作留下的资源。允许全部为空。布尔值不是整数；额外字段、重复 JSON 键、非有限数字、未知 ID、重复任务、超预算等均判非法。任一场景非法，则整次提交无排名资格。

导出的 `policy.py` 只含合法的等待动作；可替换为你的算法。也支持 `{"action": ...}` 的 JSON 文件作为常量策略对照。默认每个动作最多 2 秒，总决策时间 120 秒；主办方须在冻结提交前统一宣布不同预算。接口使用 JSON 值隔离；它不提供操作系统级恶意代码沙箱。

```bash
python3 reasoning/extreme.py --task R1 --scale full --submission /absolute/path/policy.py --output result.json
python3 reasoning/extreme.py --task R1 --scale full --export /tmp/R1-workspace
```

## 分数

每场覆盖率 `C = 总收益/全部合同原始价值`；地区公平性 `F` 为六地区中最低的同口径覆盖率。取消退款后的实际总支出记为 `S`，初始预算为 `B`。

`loss = 100×[1−(0.75C+0.25F)] + 5×S/B`

full 回放 4 组天气，smoke 回放 2 组。`objective = 0.7×平均loss + 0.3×最高10%概率质量的平均loss`，尾部边界按比例截取。`raw_score = 100/(1+objective/50)`，越高越好。赛会层面把同轮有效最高分归一化为 100，作者基线不自动满分。

## 两步思考的必要性与证据边界

一个独立穷举见证只有两个任务、容量 1 和预算 3：不扩容的最佳损失为 51.6667，先花 1 扩容再同时完成两个任务的损失为 5。单独看投资没有收益，和后续开工合并看才有收益；真实实例还要判断扩容是否值得挤掉依赖链上的其他合同。

`extreme_selftest.py` 枚举该微型问题的合法方案，并用独立公式核对裁判。作者基线只采用标准模式的价值/工期贪心；其结果是参照点，不能证明最优值或所有模型均无法求解。公开默认种子仅为演示，正式隐藏轮必须另行生成并封存种子。导出工作区不包含未来合同、未来天气、种子、参考基线或裁判。
