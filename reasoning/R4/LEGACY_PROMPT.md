# R4 · 越救越堵的在线调度中心


## 参赛题面

你管理异构工作站。任务逐步到达，有前置依赖、截止时间、优先级、可使用设备、功率需求及工艺类别。切换类别需要准备时间。设备可能突然停机，正在处理的任务会失去进度并等待重新开始。真实处理时长在开工前存在不确定性。

每个离散时刻，你只能看到当前已经到达的任务、完成记录、设备可用状态、历史工艺类别及剩余功率。返回 [{"job": "J003", "machine": 2}, ...]，也可以返回 [] 等待。不能分配尚未到达的任务、占用中的设备或未满足前置条件的任务；不能超功率。未来任务、真实未来加工时间和故障时刻不公开。


## v0.1 精确定义

60 个任务、6 台设备、300 个离散时间单位。功率容量为 10。加工时间等于公开名义时长 × 设备倍率 × 隐藏实现倍率，再向上取整；同一设备工艺类别不同则增加 3 个时间单位。隐藏倍率范围为 0.75–1.25。同一任务在同一设备的实现倍率固定，防止靠重启重抽好运气。任务不可暂停，故障后从零开始。

到期未完成的任务不能通过丢弃来提升评分。unfinished 的虚拟完成时间取 H+180，并另加未完成权重惩罚。

loss = 加权总迟延 / 总权重 + 40 × 未完成权重 / 总权重 + 0.002 × 功率时间总量 + 0.25 × max(0,开工次数-任务数)。


## 难点

最紧迫任务可能堵住某条关键依赖链；最快设备可能是后续任务唯一可用的设备；提前满载可能增加换型和故障损失。你需要决定立即执行、保留容量、选择设备和如何恢复，不存在固定的唯一排列。


## 高难档（未执行）

240 个任务、12–18 台设备，更长运行时间；跨阶段到达分布变化、资源拥塞、两个设备同时故障、稀缺设备和长依赖链。规格与分布支持范围在赛前公布。可比较滚动搜索、有限前瞻模拟、价值函数和不同分派规则。允许等待，但不允许偷看未来。


## 提交

policy.py 或等价 JSON 决策器、简短策略说明与资源使用记录。不要求提交思维链。只评价实际动作、任务结果及决策开销。

## 可见信息与动作边界

60任务、6设备、300时间单位是当前执行规模；240任务、12–18设备、分布变化等高难档尚未执行，不属于当前已验证覆盖。所有数据均为合成模拟数据。

act只接收当前观测。任务到达后才能出现在jobs中；依赖任务不会因依赖字段提前泄漏未到达任务。设备真实完成时刻、尚未到达任务表、未来停机表和场景种子不会通过act参数提供。公开演示种子用于复现，不应宣称是封存隐藏测试；正式轮次须在策略冻结后使用赛前承诺的独立种子，结束后披露复核记录。不得通过内部评测状态读取未来信息。

返回值必须是JSON数组，每一项是恰好具有job和machine两个字段的对象。job为字符串ID，machine为整数ID；布尔值true/false、1.0、NaN和Infinity不能充当machine。最多提交设备数那么多条分配；同一任务/设备不可在同一时刻被重复分配。额外字段、null、用空对象代替空数组等均为非法动作。分配按数组顺序检查，已被前项使用的资源对后项不可用。

观测是隔离的值快照，修改deps、eligible、设备状态等内容不能改变模拟器约束。策略的普通运行异常会记为非法场景；任一场景违反硬约束，该次评测valid=false，不参与最佳有效解归一化。诊断损失仍可保留用于定位。

## 时刻边界

每个时刻先结算已完成任务，再处理此刻停机并让受影响的运行任务丢失全部进度，再给出观测与接收动作。初次使用设备也需要3单位准备时间；设备类别在开工时更新，任务被中断后保留设备类别。功率时间成本逐时刻累计，故障前已经消耗的功率不退回。时间300处结算完成任务后结束，不再允许开工。

## 统一评分契约

记各场景loss的平均值为M，损失最高的10%场景概率质量的均值为T；离散样本的10%边界采用比例截取，避免向上取整后改变尾部比例。

`objective_loss = 0.8 × M + 0.2 × T`

有效提交的非负原始分为：

`raw_score = 100 / (1 + objective_loss / 10)`

原始分越大越好。该题当轮有效提交的最高raw_score换算为100竞赛分，其余为`100 × 自身raw_score / 当轮最高raw_score`；无有效正分提交时不宣布优胜者。非法提交的竞赛分为0。本题损失尺度固定为10，主办方不能在看到参赛结果后另换尺度。正确策略无需与某个预设动作序列相同，也不要求唯一最优解。
