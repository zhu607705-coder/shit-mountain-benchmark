# R3：每个探针单独都像废话，组合后才能定位

这是统一 R3 的 `extreme` 规格。**128 个组件为旧版 10 个组件的 12.8 倍；full 执行 960 次事故，为旧版 90 次的 10.67 倍。** smoke 执行 16 次事故，保持完全相同的探针与预算机制。系统合成，无真实服务数据。

每次事故恰有两个故障：组件 0–63 中均匀抽取一个，64–127 中独立均匀抽取另一个。遗漏第一个故障损失 120，遗漏第二个损失 70。你有有限诊断预算和两单位维修能力，需要决定把检查集中到哪个故障、是否校准共同噪声，以及最终采用精确修复还是昂贵的整组修复。

## 公开生成模型

故障在各自 64 组件组内的编号有 6 个二进制位。每个 bit 有一个均匀独立的隐藏 pad 位，以及一个以 0.15 概率为 1 的隐藏 drift 位。两个故障共用这六个 pad 和 drift。

可选 152 个探针（实际完整定义在 public.json）：

- ID 0–5：`pad(bit)`，成本 1，返回 pad 位。
- ID 6–11：第一个故障的 `masked(bit)`，成本 1，返回 `故障位 XOR pad位 XOR drift位`。
- ID 12–17：第二个故障的 `masked(bit)`，成本 1，返回同样方程。
- ID 18–23：`calibrate(bit)`，成本 1.5，返回 drift 位。
- ID 24–151：`direct(component)`，成本 2.5。真故障的阳性概率 0.80，否则为 0.12。但同一 64 组件组所有 direct 探针共用一个均匀噪声变量 `U`：真故障返回 `U<0.80`，非故障返回 `U<0.12`。因此这些观测条件相关，不能按相互独立的似然连乘。

同一事故中隐藏量固定；不同事故独立。禁止重复同一个探针，避免伪装成重新采样。总预算 20、最多 20 次探针，随后必须修复或结束。响应中的剩余预算是实际余额，不能修改它来获得额外检查。

一个 pad 读数本身对故障完全无信息；单个 masked 读数也无信息，因为被均匀 pad 掩盖。两者合起来才揭示带 0.15 误差的故障位，加入对应校准后才确定该位。一次 pad 还可以服务于两个故障的 masked 读数，所以分别独立解决两个故障会浪费共享信息。

## 动作、维修与评分

探针动作必须恰好为：

```json
{"test": 0}
```

终止动作必须同时且仅包含：

```json
{"repair": [12, 87], "group_repair": []}
```

`repair` 为组件整数索引数组，最多两个；`group_repair` 为组索引 0 或 1 的数组。每个精确修复占一单位维修能力，每个整组修复占两单位，所以最多两个精确修复或一个整组修复。不能重复索引，也不能对同一组同时整修和精修。

- 每个精确修复花费 4；如果修的是非故障组件，另损失 18。
- 每个整组修复花费 54，覆盖该组真实故障。
- 每个未被任何修复覆盖的故障加对应 miss_cost（120 或 70）。
- 每场 `loss = 检查实际总费用 + 修复费用 + 误修损失 + 漏修损失`。

`objective = 0.7×平均loss + 0.3×最高10%概率质量平均loss`，边界按概率质量比例截取。`raw_score = 100/(1+objective/50)`，更高更好；同轮最高有效 raw_score 再归一化为竞赛满分。没有预设正确动作序列。

任何布尔索引、浮点索引、额外字段、重复 JSON 键、NaN、重复探针、超预算、超次数、超维修能力或不终止都是非法；任一事故非法则整次提交无排名资格。

## 交互接口

提交 `policy.py`，stdin 每行读取一个观测，stdout 每行输出一个动作并 flush。持续进程可保存已收到的公开模型；`reset=true` 表示新事故。观测包含 `task/reset/episode/history/remaining_budget/max_queries`；第一步还有 `model`，后续不重复模型。历史项为 `test/result`，result 为整数 0/1。不会提供故障、pad、drift、噪声 U 或未来探针结果。

```bash
python3 reasoning/extreme.py --task R3 --scale full --submission /absolute/path/policy.py --output result.json
python3 reasoning/extreme.py --task R3 --scale full --export /tmp/R3-workspace
```

常量策略可提交 `{"action": {"repair": [], "group_repair": []}}`。默认每步最多 2 秒、全部决策时间 120 秒；主办方修改预算须在提交前对所有选手统一公布。接口对观测做值隔离；本地评测进程不构成恶意代码的操作系统沙箱。

## 难度证据与基线边界

独立枚举 8 个二元状态，可以验证 A、B、C 任意单个观测对故障都无信息，而 `A XOR B XOR C` 恢复故障位。给 drift 加正式先验后，单步 Bayes 错误率是 0.5，两步组合降低至 0.15，三步变为 0。全规模仍需在多个位、两个故障和共享校准之间分配预算；这比添加更多独立探针多出前瞻与联合后验要求。

作者基线先为损失较高的一组配对六个 pad/masked，再用剩余预算校准五个位，最后精修一个 MAP 组件。它理解互补探针，但不会联合优化第二个故障，也不搜索整组修复策略。full 结果保留实际漏修比例与尾部损失，不能用动作合法代替问题解决。

公开默认种子只用于演示，不能声称隐藏集成绩。正式赛应在冻结策略后另行生成、封存种子，赛后披露。导出包不含隐藏变量、基线、裁判或种子；尚未进行多模型难度标定，也不证明全规模最优解不可求。
