# R3 · 八次检查，找出真正值得修的故障


## 参赛题面

一个服务集群出现异常。探针会误报和漏报，一次事故可能没有故障、只有一个故障，也可能同时有两个。你获得服务候选集、各故障组合的先验概率、探针对各组合的条件响应概率、检查费用和修复损失表。真实故障组合不公开。

你需要逐次选择检查，观察检查结果，再决定继续调查或修复哪些组件。最多 8 次检查，总检查费用不得超过 9 个成本单位；允许提前停止，允许重复同一探针。最多修复两个组件。目标是最小化检查成本、漏修损失与误修代价，而不是写最长的推理报告。

接口为 act(public_model, history, remaining_budget)，返回 {"test": 整数索引} 或 {"repair": [组件索引]}。模型可以直接与此接口进行 JSON 交互；示例策略以 Python 实现。

public_model.json 包含完整字段示例。history 的每一项为 {"test": j, "positive": true/false}。测试之间在给定隐藏组合时条件独立，同一测试的重复测量也使用新观测。给定模型文件中的概率和损失是题目的正式语义。


## 什么算难

单个高相关报警不保证是最值得检查的位置。共同探针可能同时覆盖几个组件；一次看似不划算的检查可能使下一次检查非常有价值。修复两个最高后验概率组件也不一定最便宜，因为漏修代价不同。策略需要决定何时停止收集信息。


## 判分

单次 loss = 所有检查费用 + terminal_losses[修复动作][隐藏故障]。先求各场景平均损失和最差十分位均值，合成方式见下方统一评分契约。错误诊断不自动判零，它按后果扣损失。超预算、非法探针和非法修复集合违反硬约束。


## 高难档（计划规格，未在本次结果中执行）

16 个组件，含成对故障；检查预算维持紧张。改变探针覆盖结构、风险比和误报率，使用未见的服务命名与组合；对跨两步才有价值的探针安排专门场景。至少 10 个独立模型族，每族多个事故。评估策略搜索的计算成本，但不得泄露未来检查结果。


## 当前规模与可见信息

当前公开原型为10个组件、56种故障假设（无故障、单故障或双故障）、20个探针、56种修复集合。上述16组件高难档是尚未执行的后续规格，不代表本题已经覆盖该档或10个模型族。所有数据均为合成模拟数据，不是现实服务事故测量。

策略收到完整的条件概率、先验、成本和损失表；当前场景的真实故障假设、尚未发生的检查结果与抽样种子不会出现在act参数中。history只包含已经选择并执行的检查。公开演示种子用于复现，不应宣称是封存隐藏测试；正式轮次须在策略冻结后使用赛前承诺的独立种子，并在结束后披露复核记录。

## 严格动作协议与失败处理

返回值必须是一个普通JSON对象，且恰好包含test或repair其中一个字段。test必须是整数索引；repair必须是最多两个互不重复的整数索引构成的数组，允许空数组和任意顺序。布尔值true/false不能充当索引，1.0也不视为整数索引；NaN、Infinity、额外字段、空对象、返回null等均为非法动作。组件索引与探针索引必须存在于输入模型中。

输入是与模拟器状态隔离的值快照。修改模型、成本、预算或history不能更改主办方计分和真实历史。策略抛出普通运行异常会被记为非法场景，不能中断其他参赛者的结果记录。任一场景违反硬约束，整个该次评测valid=false，不参与最佳有效解归一化。诊断损失仍可保留用于定位。

## 统一评分契约

记各场景loss的平均值为M，损失最高的10%场景概率质量的均值为T；离散样本的10%边界采用比例截取，避免向上取整后改变尾部比例。

`objective_loss = 0.8 × M + 0.2 × T`

有效提交的非负原始分为：

`raw_score = 100 / (1 + objective_loss / 10)`

原始分越大越好。该题当轮有效提交的最高raw_score换算为100竞赛分，其余为`100 × 自身raw_score / 当轮最高raw_score`；无有效正分提交时不宣布优胜者。非法提交的竞赛分为0。本题损失尺度固定为10，主办方不能在看到参赛结果后另换尺度。正确策略无需与某个预设动作序列相同，也不要求唯一最优解。
